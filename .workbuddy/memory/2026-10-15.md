## 排查「declares no dsh.bundle」安装报错

- 用户安装时报错。拉取 @deepseek-ai/dsh@0.2.0-rc.2 + @deepseek-ai/dsh-plugin-manager@0.2.0-rc.2 源码分析：插件安装校验只要求 package.json 的 `dsh.bundle` 是非空对象（inspectionOf），reconcile 阶段再查 `dsh.bundle.patch`
- 根因：npm 上 0.0.0-stage（17:10:09 先发，整个 dsh 字段缺失）被安装时解析命中；0.1.0（17:11:29 后发，dsh.bundle 正确）才是修复版。代码本身无问题
- 0.1.0 tarball 验证完整（7 文件，含 cordis.patch.yml）
- 解决：重跑 dsh plugin add；必要时精确指定 @0.1.0 或 unpublish 0.0.0-stage

## 修复「cannot get property webServer without inject」host 半激活失败

- 根因（源码级定位 + cordis 4.0.4 最小 fiber 树 lab 复现）：connection.rpc.handle() 内部 get rpc() 的 owner=this.ctx 经 cordis Service tracker shadow 重绑回 dsh-client-connection 自己的 fiber（其 inject 仅 ["credentials"]），owner.webServer 解析必然失败；插件自声明 inject 无济于事
- 生态标准模式（side-panel/better-sidebar 均如此）：inject=['webServer'] + ctx.webServer.register prefix 路由 + 纯 JSON
- 重写 lib/index.js（webServer 路由 + loopback/origin 围栏，响应保持 {ok,value} 外形）、lib/client.js（fetch 替代 rpc.call，client inject 去掉 connection）、cordis.patch.yml 注释、package.json 0.1.1（去 cordis peer）、CHANGELOG、README
- lab-e2e：真实 http server + 真实 lib/index.js，激活 state 2，搜索 200、GET 405、恶意 origin 403、include/regex 全通过
- 0.1.1 待用户发布（未动 git/npm）
- 关键教训：dsh 第三方插件给浏览器开路由，永远用 ctx.webServer.register，别碰 connection.rpc.handle
